# 作業計画

**この文書は、決めたこと（理由と前提）、見送った案、未決事項、残りの作業、経緯を持つ。**
読者は AI。経緯はこの文書にだけ書く。

## 目的

出所：`doc/initial_prompt.txt`（利用者による最初の依頼文）

- MGA を経由して、Y8960 Cartridge の FPGA とファームウェアを更新する PC 用ツールを作る
- 対象は Windows と Linux
- `../Y8960_Cartridge` の `Y8960UPD.COM`（MSX-DOS 用）と同等の機能を持つ。ただし ROM は
  生の `.rom` ファイルを受け付ける
- 実カートリッジとのインターフェースは `../MSXPLAYer_GameAdapter` を使う
- C++ / CMake / vcpkg
- 主な用途は、利用者の側で作っている BIOS（MsxSoundSuiteExtension の `y8960bas.rom`）を
  実カートリッジに書き込むこと（利用者の言、2026-11-02）

## 決めたこと

各項目に「理由」と「前提（これが変わらない限り成立する）」と「変えるときの値段」を書く。

### 2. 公開する。ライセンスは MIT、著作権表記は `MadScient`

- 理由：利用者の決定（2026-11-02）。原本の Y8960UPD とアダプタがどちらも MIT。著作権表記は

- ソースの冒頭は `SPDX-License-Identifier: MIT` と著作権表記の 2 行

### 3. `CLAUDE.md` は追跡し、手元に固有のことは `CLAUDE.local.md`（追跡外）に書く

- 理由：利用者の決定（2026-11-02）。初期の依頼文が `CLAUDE.md` をリポジトリの構成に含めている

- 理由：バイナリの扱い（`std::span` など）。MSVC と g++ の両方で使える

### 5. 依存ライブラリ無しで始める

- 理由：シリアル通信は、アダプタの公式ダンパー（Win32）と mgadump（termios）に実装と知見が
  あり、MGA に固有の同期（前回の残りの読み捨てなど）はどのライブラリを使っても自前で書く
- 前提：単体試験の枠組みや引数の解析で必要になれば、`vcpkg.json` に足す
- vcpkg の toolchain はプリセットで常に渡しておく（依存を足すときに手順が変わらない）

### 6. 改行は LF

- 理由：兄弟の mgadump と同じ。Windows 側と WSL 側の git から同じに見える

- 理由：Windows と WSL で同じ作業ツリーを使ってもビルド先が混ざらない
- プリセットの構成は利用者の別のリポジトリに倣った

### 8. 主ブランチは `main`

- 理由：利用者の決定（2026-11-02）。GitHub で新しく作るリポジトリの既定に合う。参照先の
  `Y8960_Cartridge`・`MSXPLAYer_GameAdapter`、兄弟の mgadump も `main`
- 値段：公開の前なら `git branch -m` だけ。公開の後は、クローンした人の追従が要る

### 9. 初期の依頼文の「FPGA」は Config data、「ファームウェア」は BIOS data を指す

- 理由：利用者の確認（2026-11-02）。原本の言葉（`Y8960UPD.COM` の Config data / BIOS data）に
  対応させた
- 文書とコードでは原本の言葉（Config data / BIOS data）を使う

### 10. 「生の .rom」は BIOS data の本体（ヘッダの無い 128KB）を指す

- 理由：利用者の確認（2026-11-02）。MsxSoundSuiteExtension の成果物 `y8960bas.rom` を、
  ヘッダを付けずにそのまま書けるようにする。原本の `tool/bios/mk.bat` は `header.bin` ＋
  `y8960bas.rom` で BIOS data を作り、Windows 版の readme は「ヘッダなしの `y8960bas.rom` は
  選択できません」と書いている
- 前提：BIOS data の本体が 128KB ちょうどである（原本の asm が `20000h` を要求する）

### 11. 生の .rom のバージョン情報文字列はオプションで指定し、省略したら空にする

- 理由：利用者の決定（2026-11-02）。ROM の中にリリースの版が入っていない（`MSSE8960V1.0 2026 10 31`
  のような文字列はモジュールの版。0.5.4 の `y8960bas.rom` で見た）。開発中の版を何度も書き直すので、
  毎回の指定を求めない。省略して前の版の文字列を残すと、表示と中身が食い違う
- 「空」は 16 バイトすべて `00h`。原本の表示では `(none)` になる（`doc/spec.md` の 3 章）
- オプションの名前と書式は、コマンドラインの書式（未決事項）と一緒に決める
- 前提：ヘッダ付きの BIOS data では、従来どおりヘッダの +32 を使う

### 12. Config data はヘッダ付きだけを受け付ける

- 理由：利用者の決定（2026-11-02）。Config は原本の作者の成果物で、この道具の用途（「目的」の節）には
  要らない。ヘッダが無いとシグネチャで取り違えを弾けず、書き損じると MGA からは
  直せない（`doc/spec.md` の 6 章、推測）

### 13. コマンドラインは原本の `/` を `-` に替えた形

- `y8960upd_gca`（引数なし）でバージョンの表示、`-c ファイル` で Config data、`-b ファイル` で
  BIOS data、`-h` で使い方
- 理由：利用者の決定（2026-11-02）。原本を知る人が迷わない。Linux では `/C` が絶対パスと紛らわしい
- 値段：`src/cli/`、`doc/manual.md`、`README.md`、試験

### 14. 生の .rom のバージョン情報文字列は `--bios-version 文字列` で渡す

- 理由：利用者の決定（2026-11-02）。`--version` はツール自身の版の表示に使われることが多い
- 16 バイトより短ければ残りを `00h` で埋める（原本の形式）

### 15. `-c` と `-b` を 1 回の実行で両方指定できる

- 理由：利用者の決定（2026-11-02）。Config → BIOS の順に書き、バージョンのブロックは最後に
  1 回だけ書き換える。片方だけも指定できる
- 前提：片方が失敗したら、もう片方にも進まず、バージョンのブロックも書き換えない

### 16. ポートは VID:PID で自動で探し、`--port` で指定もできる

- 理由：利用者の決定（2026-11-02）。複数台が見つかれば一覧を表示して止まる。ほかの機器には
  何も送らない

### 17. `--bios-version` の誤り

- 16 バイトを超える文字列と、表示できない文字（`20h` 未満、`7Fh` 以上）を含む文字列は誤りにする。
  ヘッダ付きの BIOS data に `--bios-version` を付けたときも誤りにする
- 理由：利用者の決定（2026-11-02）。黙って切り詰めたり置き換えたりすると、表示と中身が食い違う
- どの誤りも、カートリッジに触る前に止まる

### 18. 消去の後の確かめは原本と同じ（ブロックの先頭 256 バイト）

- 理由：利用者の決定（2026-11-02）。ブロック全体を読むと 1 ブロックにつき約 6 秒増える ― 推測
  （読み出しの測定からの比例）。書き込みの後のベリファイは本体の全体を読む
- 前提：BUSY を見たことも確かめる（原本と同じ）

### 19. 単体の試験は Catch2 3。vcpkg のマニフェストに入れ、見つからなければ単体の試験を飛ばす

- 理由：`doc/design.md` の試験の方式。vcpkg を使わない Linux のビルドでも、ツールは組めるようにする
  （Ubuntu では apt の `catch2` で単体の試験も組める）
- 値段：`vcpkg.json`、`test/CMakeLists.txt`、`README.md`

### 20. 原本に無い表示と終了コード

### 21. Ctrl+C で止めたときも `40h` に `00h` と `SPOFF` を送る

- 理由：利用者の決定（2026-11-02）。カートリッジの電源を入れたまま残さない
- 表示は改行の後に `Interrupted.` の 1 行。終了コードは 130（シェルの慣例の 128 ＋ SIGINT。Windows でも
  同じ値）。書きかけの注意の 2 行目は出さない
- バージョンのブロックを消してから書き戻してベリファイするまで（約 1 秒）は、止める求めを後回しにする。
  この間に止めると両方のバージョンが消えるため
- 2 回目はすぐに終わる（応答しない MGA で止まらないように）。電源は切らない。終了コードは 130
- 対象は Ctrl+C、Linux の SIGTERM、Windows の Ctrl+Break。Windows のウィンドウを閉じる操作は扱わない
  （ハンドラから戻るとすぐに終了させられる）
- 表示、終了コード、後回し、対象は、利用者が推奨の案を選んだ（2026-11-02。返事は「A」の一語で、
  すべての問いの推奨が A だったので、全部 A と読んだ）。2 回目で電源を切らないのは、すぐに終わることの
  帰結として AI が書いた
- 作り：`doc/design.md` の MGA とコマンドラインの節。止める求めは、コマンドを送る直前にだけ見る
- 前提：Config の途中で止めたときも電源を切る。変えるかは未決事項（DOCK で確かめてから）
- 値段（表示と終了コードを変えるとき）：`src/cli/cli.hpp` の定数と `cli.cpp` の文字列、試験、
  `doc/manual.md`

### 22. 圧縮された Config data・BIOS data を受け付ける

- 理由：利用者の決定（2026-11-02）。原本の v0.9.6 から、配布の `Y8960CFG.BIN` が圧縮されている。
  原本の作者が `805d900` で圧縮に対応した asm を push し、形が一次の資料で分かった（`doc/spec.md` の
  2 章）。原本の `mk.bat` は BIOS data も圧縮するので、BIOS data も受け付ける
- 聞かずに決めたこと（構造から決まる。2026-11-03 に利用者へ報告した）
  - 展開は、カートリッジに触る前にファイル全体で済ませる。「書き込みの前に両方のファイルを検査する」
    （`doc/design.md` のコマンドライン）に合わせた。原本の MSX 版は消去の後に展開しながら書くので、
    壊れたファイルでも消去まで進む
  - 圧縮した BIOS data に `--bios-version` を付けたら、ヘッダ付きと同じく誤り（決めたこと 17）
  - 生の BIOS の判定は、シグネチャの 31 バイトで見る。+31 が `02h` 以上のヘッダ付きのファイルが
    ちょうど 128KB のとき、生の BIOS として通らないようにする
  - ブロックの大きさは 1〜16384 を受け付ける（asm と Windows 版。パッカーの `-u` は 16384 だけ。
    `CLAUDE.md` の「食い違えば asm を正」）
  - 16MB 以上のファイルは、+31 にかかわらず大きさの誤り。パッカーと同じ 16384 のブロックなら、
    Config の上限（`7D0000h`）を格納ブロックで入れても約 8.2MB。ブロックを小さくした 16MB 以上の
    ファイルは、asm なら通るがこのツールは断る（asm は圧縮したファイルの大きさを見ない）。利用者への
    最初の報告では「正しい圧縮ファイルは最大でも約 8.2MB」と書いたが、16384 のブロックに限った話だった
- 前提：原本の形式（`doc/spec.md` の 2 章の「圧縮形式」）が変わらない。+31 に `02h` 以上の形が
  足されたら、その値を受け付けるかを決め直す
- 値段（形式が変わったとき）：`src/image/`、試験、`doc/spec.md`・`doc/design.md`・`doc/manual.md`

### 24. 壊れた圧縮ファイルは、Windows 版とパッカーと同じだけ断る

  参照する ZX0 も断る（原本の MSX 版は見ない。`doc/spec.md` の 2 章の表）
- 理由：利用者が推奨の案を選んだ（2026-11-03）。形式にチェックサムが無く、Config を書き損じると MGA
  からは直せない。正しいファイル（v0.9.7 の `Y8960CFG.BIN` で確かめた）はどちらの案でも通る
- 値段：`src/image/` の検査の数行と試験、`doc/manual.md` の表

### 25. 圧縮ファイルの誤りの文言は、原本の MSX 版の分け方に揃える

- ファイルが途中で切れている（54 バイトに満たない、フレームが切れる）：`File read error.`
- +31 が `02h` 以上、ブロックの大きさ・フレームの長さが不正、最後のフレームの後に余りがある：

  `Decompress error.`（asm の新しい文言）
- 展開した大きさが範囲の外：`Invalid data size.`。asm と同じく、展開した大きさの上位 8 ビットを
  ブロックの大きさより先に見る
- 終了コードはどれも 2（ファイルの誤り。決めたこと 20）
- 理由：利用者が推奨の案を選んだ（2026-11-03）。原本の文言は原本に揃える（決めたこと 20）
- 前提：原本の asm の文言が変わらない
- 値段：`src/image/image.hpp` の `Reason`、`src/cli/cli.cpp` の文字列、試験、`doc/manual.md` の表

## 見送った案

- `CLAUDE.md` 全体を追跡の外にする（mgadump の形）。見送った理由：初期の依頼文が
  `CLAUDE.md` をリポジトリの構成に含めている。利用者が `CLAUDE.local.md` に分ける案を選んだ
- 生の .rom のバージョン情報文字列の指定を必須にする案と、省略したらバージョン領域を
  書き換えない案。見送った理由は「決めたこと」の 11
- ヘッダの無い Config の `.bin` を受け付ける案。見送った理由は「決めたこと」の 12
- コマンドラインをサブコマンド（`info`・`config`・`bios`）にする案と、原本と同じ `/` の形に
  する案。見送った理由は「決めたこと」の 13
- 1 回の実行で片方だけを書く案（原本の MSX 版の形）と、ポートを常に `--port` で指定する案。
  見送った理由は「決めたこと」の 15 と 16
- `--bios-version` の長すぎる文字列を切り詰める案、ヘッダ付きの BIOS data の値を置き換える案、
  消去の後にブロック全体を確かめる案。見送った理由は「決めたこと」の 17 と 18
- カートリッジの J3 の JTAG から、外付けのケーブル（利用者の手元の Altera USB Blaster に変換を
  はさむ形、または Gowin 純正の GWU2X のケーブル）で Config を書いて復旧する案。見送った理由：
  原本の作者の返事で、カートリッジの JTAG からは Config ROM を書けない（2026-11-02）。理由は
  聞いていない。調べたこと（J3 と両ケーブルのピン配置、VCC の電圧の条件、openFPGALoader の対応と
  issue #557）は `d245268` の plan の未決事項にある
- 壊れた圧縮ファイルの検査を原本の MSX 版（asm）に揃える案、圧縮に関わる誤りを全部
  `This file is not a valid image for this option.` にする案（Windows 版の形）、ZX0 の展開を MIT だけで
  持つ案。見送った理由は「決めたこと」の 24〜26

## 未決事項

- 電源を入れてから System Controller を触るまでの待ち方。MGA は /WAIT を見ないので、
  起動時の BIOS のコピーの終わりを MGA が待ってくれない（`doc/spec.md` の 6 章）。
  1 回の測定では、`SPON` から 115ms で `40h` が `7Fh` を返した。コピーの終わりとの関係は
  まだ分からない
- DOCK を使う場面。Config の書き込みは、DOCK が届く前に MGA から実機で通った（2026-11-02、`doc/spec.md` の
  6 章）。利用者が「壊れてもこのリポジトリの作業が数日止まるだけ」と判断し、同じ版の 0.9.3 から試した。
  DOCK は書き損じたときの復旧の手段として残る。原本の作者の返事（2026-11-02、利用者が渡したチャットの
  画面）：カートリッジの JTAG からは Config ROM を書けない。MSX-DOS の `Y8960UPD.COM` で更新できる。
  DOCK があれば TangPrimer25K をそちらに付け替え、`Y8960UpdWin.exe` で PC から書ける。DOCK は単体では
  売っていない。届いたら、復旧の道（付け替えて書き、戻して起動を見る）を一度通すかは利用者に聞く
- Config の消去・書き込みの途中で止まったとき（Ctrl+C でも誤りでも）に電源を切るか。切ると、次に電源を
  入れたときに FPGA が壊れた Config から起動しようとして動かなくなる ― 推測。入れたまま終われば、FPGA は
  動き続け、もう一度走らせれば書き直せるかもしれない ― 推測（アダプタの `cmd_slotPowerOn` は、電源が
  入っていれば入れ直さず RESET を振るだけ。原本 `3624849` の RTL・制約・ネットリストを `reconfig` で
  探して 0 件）。今は決めたこと 21 のとおり常に切る。DOCK が届いて、壊れても戻せる状態で確かめてから
  決める（利用者の決定、2026-11-02）。値段：電源を切る処理の分岐と表示の 1 行、試験、manual の注意
