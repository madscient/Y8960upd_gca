## 目的

出所：`doc/initial_prompt.txt`（利用者による最初の依頼文）

- MGA を経由して、Y8960 Cartridge の FPGA とファームウェアを更新する PC 用ツールを作る
- 対象は Windows と Linux
- `../Y8960_Cartridge` の `Y8960UPD.COM`（MSX-DOS 用）と同等の機能を持つ。ただし ROM は
  生の `.rom` ファイルを受け付ける
- 実カートリッジとのインターフェースは `../MSXPLAYer_GameAdapter` を使う
- C++ / CMake / vcpkg
- 主な用途は、利用者の側で作っている BIOS（MsxSoundSuiteExtension の `y8960bas.rom`）を
  実カートリッジに書き込むこと（利用者の言、2026-11-02）

- 文書とコードでは原本の言葉（Config data / BIOS data）を使う

### 10. 「生の .rom」は BIOS data の本体（ヘッダの無い 128KB）を指す

- 理由：利用者の確認（2026-11-02）。MsxSoundSuiteExtension の成果物 `y8960bas.rom` を、
  ヘッダを付けずにそのまま書けるようにする。原本の `tool/bios/mk.bat` は `header.bin` ＋
  `y8960bas.rom` で BIOS data を作り、Windows 版の readme は「ヘッダなしの `y8960bas.rom` は
  選択できません」と書いている
- 前提：BIOS data の本体が 128KB ちょうどである（原本の asm が `20000h` を要求する）

### 11. 生の .rom のバージョン情報文字列はオプションで指定し、省略したら空にする

- 理由：利用者の決定（2026-11-02）。ROM の中にリリースの版が入っていない（`MSSE8960V1.0 2026 10 31`
  のような文字列はモジュールの版。0.5.4 の `y8960bas.rom` で見た）。開発中の版を何度も書き直すので、
  毎回の指定を求めない。省略して前の版の文字列を残すと、表示と中身が食い違う
- 「空」は 16 バイトすべて `00h`。原本の表示では `(none)` になる（`doc/spec.md` の 3 章）
- オプションの名前と書式は、コマンドラインの書式（未決事項）と一緒に決める
- 前提：ヘッダ付きの BIOS data では、従来どおりヘッダの +32 を使う

### 12. Config data はヘッダ付きだけを受け付ける

- 理由：利用者の決定（2026-11-02）。Config は原本の作者の成果物で、この道具の用途（「目的」の節）には
  要らない。ヘッダが無いとシグネチャで取り違えを弾けず、書き損じると MGA からは
  直せない（`doc/spec.md` の 6 章、推測）

## 未決事項

- コマンドラインの書式（原本の `/C`・`/B` に倣うか、ポートの指定をどうするか）。外に出る値
- MGA のポートの見つけ方（VID:PID で選ぶか、HVER で探るか）
- 片方だけの更新を許すか。原本の MSX 版は、もう片方のバージョンを読み戻してから
  バージョンのブロックを書き直す（asm の `update_version` で確かめた。`doc/spec.md` の 3 章）。
  MGA の I/O で ConfigROM を読み戻せることは実機で確かめた（`doc/spec.md` の 6 章）ので、
  原本と同じく片方だけの更新ができる見通し。消去と書き戻しはまだ試していない
- 電源を入れてから System Controller を触るまでの待ち方。MGA は /WAIT を見ないので、
  起動時の BIOS のコピーの終わりを MGA が待ってくれない（`doc/spec.md` の 6 章）。
  1 回の測定では、`SPON` から 115ms で `40h` が `7Fh` を返した。コピーの終わりとの関係は
  まだ分からない
- 書き込みの方式。PC との 1 往復が約 1.0ms で、1 バイトの読み出しに 7 往復かかった
  （実機で測った）。1 往復ずつ送る方法では、128KB の読み出しだけで約 16 分になる ― 推測
  （測った値からの比例）。スクリプトモード（`BRCV` ＋ `BSCR`）で、書き込みと待ちを MGA 側で
  回す形が候補。1 バイトの書き込みは約 15 命令（60 バイト）で、1 回のスクリプトで約 1,000
  バイト ― 推測（`doc/spec.md` の 4 章の手順から命令を数えた。アドレスの 3 バイトを毎回
  書く前提）。スクリプトの速さは実機で測る
- Config の書き込みを実機で試すかどうかと、その前の復旧の手段。利用者の手元の個体は
  TangPrimer25K に USB の口が無く、書き損じると PC から直せない（`doc/spec.md` の 6 章）
